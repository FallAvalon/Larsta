# Larsta

[English version](README.md)

Приложение для чатов с персонажами на своём сервере: React, TypeScript, Vite, Node.js и SQLite. Поддерживает OpenRouter, LM Studio, Ollama, OmniRoute, Polza.ai и произвольные OpenAI-совместимые API. Компьютер и телефон используют общую библиотеку и переписку.

Публичная версия запускается с пустой библиотекой. Необязательный пример `examples/character-v2.json` — специально придуманный библиотечный проводник для демонстрации и тестов. Личных персонажей, переписок, изображений, ключей и сохранённых настроек в исходниках нет.

## Запуск

Установите Node.js **22.13 или новее** с npm. В папке проекта выполните:

```sh
npm ci
npm run build
npm start
```

В Windows можно дважды нажать `start.cmd`, в Linux — выполнить `bash start.sh`. Скрипты устанавливают зависимости при необходимости, собирают и запускают приложение. Оставьте терминал открытым; остановка — Ctrl+C.

1. Откройте `http://localhost:3000` и введите код подключения из терминала.
2. В **Настройки → Модель** измените существующее подключение OpenRouter или нажмите **Добавить**. Сохраните подключение, выберите его и модель, затем **Сохранить изменения**. Модель не выбирается автоматически. Доступность, стоимость и лимиты зависят от провайдера.
3. Создайте персонажа или импортируйте пример JSON из `examples/`. Откройте карточку и начните чат.
4. В **Настройки → Оформление → Язык интерфейса** выберите **Русский** или **English**. При первом открытии язык определяется браузером. Язык и оформление сохраняются отдельно на каждом устройстве; тексты персонажей и переписки не переводятся автоматически.

Для телефона в той же доверенной сети Wi-Fi откройте сетевой адрес из терминала и введите тот же код. При необходимости разрешите Node.js доступ через брандмауэр в частной сети. Компьютер должен работать. Соединение использует HTTP: не открывайте порт в интернет и не передавайте код посторонним. Все подключённые устройства имеют полный доступ. Подробнее — [SECURITY.md](SECURITY.md).

## Возможности

- Библиотека персонажей: поиск, избранное, теги, портреты, импорт и экспорт Character Card V2 JSON. Изображения загружаются отдельно и не встраиваются в JSON. Некоторые расширения V2 сохраняются без исполнения.
- Несколько персон, профиль по умолчанию и отдельная копия персоны для каждой истории.
- Потоковые ответы, редактирование сообщений, варианты, пожелания при перегенерации, продолжение ответа, ветки и откат с сохранением прежней истории.
- Независимый провайдер и модель для каждого чата, бюджет контекста, отображение размышлений по желанию, загрузка истории частями и восстановление места чтения.
- Мобильная навигация, меню без рамок, настройка шрифтов и цветов, анимации кнопок и поддержка уменьшения движения.
- Несколько подключений одного провайдера, ключи на сервере, проверка подключения и генерации, сессии устройств, восстановление подписки на генерацию, автоматические резервные копии и восстановление через командную строку.

Каталог моделей обновляется в настройках; ручной ID работает и при недоступном каталоге. Приложение не подставляет другого провайдера или модель автоматически. Необязательный профиль совместимости OpenCode меняет заголовки атрибуции только для OpenRouter; ограничения провайдера продолжают действовать. Поле вспомогательной модели оставлено в формате данных для совместимости, но вызовов к ней нет.

## Провайдеры и модели

У каждого подключения своё название, адрес API, режим авторизации, ключ и параметры совместимости. Можно добавить два подключения OpenRouter с разными ключами или несколько локальных серверов. Пресеты задают начальные значения; любой адрес можно изменить:

| Провайдер | Начальный Base URL | Авторизация по умолчанию |
| --- | --- | --- |
| [OpenRouter](https://openrouter.ai/docs/api_reference/overview) | `https://openrouter.ai/api/v1` | Bearer-ключ |
| [LM Studio](https://lmstudio.ai/docs/developer/openai-compat) | `http://localhost:1234/v1` | Без ключа; включите Bearer, если он требуется вашему серверу |
| [Ollama](https://docs.ollama.com/api/openai-compatibility) | `http://localhost:11434/v1` | Без ключа |
| [OmniRoute](https://github.com/cheaper-inference/OmniRoute) | `http://localhost:20128/v1` | Без ключа; настройте ключ, если он требуется вашему развёртыванию |
| [Polza.ai](https://polza.ai/docs/api-reference/introduction) | `https://polza.ai/api/v1` | Bearer-ключ |
| OpenAI-совместимый API | Ваш адрес API | Настраивается |

Запросы отправляет сервер Larsta. **localhost означает компьютер с запущенной Larsta**, в том числе при использовании телефона. Для сервера моделей на другом компьютере укажите его сетевой адрес и разрешите доступ в настройках этого сервера. Локальный сервер должен быть запущен, а модель — доступна в нём. Larsta не устанавливает и не загружает модели.

Указывайте корень API с нужным префиксом, например `/v1` или `/api/v1`, без `/chat/completions` и `/models`. Larsta сохраняет пользовательский префикс и не угадывает его. Ключ вводится в отдельное поле, а не в URL. Проверка TLS не отключается, запросы не следуют перенаправлениям.

**Проверить подключение** запрашивает каталог без генерации. Для OpenRouter и Polza.ai дополнительно проверяется ключ через `/key`. У других API каталог может быть публичным: его доступность не доказывает доступ к модели или правильность ключа. **Проверить генерацию** отправляет короткий синтетический запрос точной модели из поля проверки; провайдер может списать оплату. Карточка и переписка не передаются, сообщения не сохраняются. Рассуждающая модель может исчерпать небольшой тестовый лимит до появления текста. Проверки используют текущие поля формы и не сохраняют подключение.

В разделе **Совместимость** можно выбрать поле лимита ответа (`max_tokens`, `max_completion_tokens` или не отправлять), передачу температуры и формат рассуждения. Поля маршрутизации и заголовки OpenRouter передаются только его подключениям. Отсутствие метаданных не считается запретом параметров или нулевой ценой. Валюта каталога сохраняется, включая RUB у Polza.ai. Цены задаёт провайдер; это не расчёт фактического списания в Larsta.

В чате откройте **Модель и ответы → Для этого чата**, выберите провайдера и модель и сохраните. Режим **Общие** возвращает наследование. Ветки сохраняют настройки чата, варианты ответа — сведения о своём провайдере. Смена подключения не сбрасывает историю. Перед удалением подключения замените его в общих настройках и закреплённых за ним чатах; исторические сообщения при удалении сохраняются.

Генерация использует настройки, выбранные в начале запроса. Изменение и удаление занятого подключения блокируются до остановки ответа. Каталоги кешируются отдельно для каждого подключения и ключа. Недоступный каталог не задерживает генерацию по ручному ID. При ошибке или обрыве Larsta не повторяет генерацию с другой моделью. Неверный ключ провайдера не отключает устройство от Larsta.

## Данные и резервные копии

Во время работы создаётся папка `data/`: база `larsta.sqlite` с возможными служебными файлами SQLite, `uploads/`, `backups/` и `server-secrets.json`. Вся папка приватная. Черновики, место чтения, язык и оформление хранятся в браузере. Выбранный контекст истории передаётся провайдеру модели.

Автоматические копии содержат базу, настройки подключений и загруженные изображения, но не серверные секреты. Перед обновлением остановите сервер и сохраните приватную копию приложения и **всей папки `data/` вне установки**, включая `server-secrets.json`. Проверьте восстановление в отдельной папке до замены установки. Нельзя копировать работающую SQLite-базу без её подтверждённых данных WAL.

Обновление провайдеров переводит схему 6 в 7 аддитивно, после проверенной резервной копии. Настройки и ключ OpenRouter сохраняются. Чаты со своим прежним ID модели закрепляются за перенесённым подключением OpenRouter; чаты с общими настройками продолжают их наследовать. Персонажи, персоны, ID сообщений, варианты, ветки, изображения и сессии устройств сохраняются. Повторный запуск не повторяет перенос секретов. Старая Larsta откажется открывать новую схему: для возврата используйте соответствующую приватную копию приложения и данных.

После сборки доступны команды:

```sh
npm run backup -- list
npm run backup -- create
npm run backup -- verify BACKUP_ID
npm run backup -- restore BACKUP_ID --confirm
```

Перед `create` и `restore` остановите сервер. Восстановление сохраняет прежние данные в отдельной папке для возврата. Не публикуйте резервные копии.

Переменные окружения: `PORT` (по умолчанию `3000`), `LARSTA_DATA_DIR` (по умолчанию `data`), `OPENROUTER_API_KEY` (приоритетнее сохранённого ключа только для исходного подключения на адресе OpenRouter). Дополнительные аккаунты OpenRouter используют собственные сохранённые ключи. Источник ключа виден в редакторе; для изменения ключа из окружения обновите окружение и перезапустите Larsta. Файлы окружения и секреты нельзя коммитить.

## Разработка и проверки

```sh
npm run dev
npm run check
npm test
npm run build
node --test tests/publication.test.mjs
npm run test:ui
```

Браузерные проверки `tests/ui-*.mjs` работают с временными данными и подставными провайдерами, без запросов к реальным аккаунтам моделей. Playwright включён в зависимости для разработки. После сборки запустите все восемь сценариев через `npm run test:ui` или отдельный файл, например `node tests/ui-providers.mjs`. По умолчанию используется установленный Chrome. Другой вариант: `npx playwright install chromium` и переменная `LARSTA_BROWSER_CHANNEL=chromium` (`$env:LARSTA_BROWSER_CHANNEL='chromium'` в PowerShell). `LARSTA_PLAYWRIGHT_MODULE` позволяет указать другой установленный модуль Playwright. Скриншоты в `test-results/` остаются локальными и не входят в публикацию. Автоматические проверки протокола не подтверждают доступность каждого реального сервиса и не заменяют визуальную проверку.

## Подготовка к публикации

Не отправляйте в GitHub рабочую установку целиком. Git разрешает только явно перечисленные исходники; дополнительная проверка готовит отдельную копию:

```sh
npm run public:check -- --private-dir data
npm run public:prepare -- --out /path/to/new-public-folder --private-dir data
```

Папка назначения должна быть новой и находиться вне рабочей установки. Скрипт копирует только разрешённые файлы и синтетический пример, затем проверяет результат. При `--private-dir` имена, идентификаторы, ключи, настройки и текстовые отпечатки приватных данных сравниваются локально без вывода их значений. Перед публикацией проверьте копию и список подготовленных файлов. Если прежняя история Git могла содержать личное, начните новую историю. Подробнее — [SECURITY.md](SECURITY.md).
